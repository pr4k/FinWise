# API specification export

Snapshot of `backend/openapi.json`, generated by `scripts/generate_contract.py`. Base URL: `/api/v1`. OpenAPI 3.1.0. The JSON file contains request and response schemas, headers, status codes, and examples where defined. This catalog lists every operation and its declared availability.

**Status:** `x-implemented: true` means a route is declared active by the contract; it does not imply the full product feature spec is complete. `false` returns `501 not_implemented` after authentication for protected routes. Unknown API paths return `404`.

## Calling conventions

- Authentication uses a `finwise_session` cookie. `POST /auth/login` and bootstrap issue the cookie and CSRF token. Mutating authenticated requests send `X-CSRF-Token`.
- Use `Idempotency-Key` where the OpenAPI operation requires it; use `If-Match` or `expected_revision` for revision-checked changes.
- JSON money values are decimal strings. Dates use `YYYY-MM-DD`; month identifiers use `YYYY-MM`; amounts are not JSON floats.
- Financial responses normally use `Cache-Control: no-store`. The enabled anonymous widget responses can be cached privately for five minutes.
- `POST /imports` uses multipart form data. `GET /jobs/{job_id}/events` is SSE. The remaining documented routes use JSON unless the operation specifies another content type.
- The separately enabled quick expense and widget APIs are public routes intended for trusted private networks; review their settings before exposure.

## Contract sources and drift

The source generator is `scripts/generate_contract.py`; it writes `backend/openapi.json` and `web/src/lib/api/types.ts`. The server publishes the bundled contract at `/api/v1/openapi.json`. Regenerate and run `python3 scripts/generate_contract.py --check` after route/schema changes, then refresh this snapshot. Product behavior details live in `../api-spec.md` and module documents; those documents can describe target features beyond this release.
